# Codex Config TOML Editor

[English](README.md) | 日本語 · [変更履歴](CHANGELOG.ja.md)

リポジトリの `.codex/config.toml` をVSCodeで編集する拡張機能です。ファイル保護、モデルなどの基本設定、設定の診断をひとつの画面で管理できます。

## 主な機能

- ファイル・フォルダー・globパターンによる読み取り禁止ルール
- `.env`・秘密鍵のプリセット、保護候補と一致するファイルの確認
- モデル・推論の強さ・承認方針・Web検索の編集
- 設定元の比較、TOML構文や旧sandbox設定との競合の診断
- コメントや未編集項目を維持した保存、保存前の差分確認と外部変更の検出

編集対象はワークスペース直下の `.codex/config.toml` です。共通設定は変更しません。保護候補の内容を読んだり、設定値やパスを外部サービスに送信したりする処理はありません。

## 使い方

VSCode 1.120以降が必要です。拡張機能画面の「…」から **VSIXからのインストール** を選び、この拡張機能の `.vsix` ファイルを指定してください。

1. リポジトリを開き、コマンドパレットから **Codex Config TOML Editor: リポジトリ設定を開く** を実行します。
2. 「ファイル保護」で相対パスやglobパターンを追加します。
3. **対象ファイルを確認** で一致するファイルを確認します。
4. **差分を確認** を押し、内容を確認して **確認した変更を保存** を押します。
5. Codexでプロジェクトを信頼し、新しいセッションで設定を確認してください。

エクスプローラーの右クリックから **Codex Config TOML Editor: このファイル・フォルダーの読み取りを禁止** でも追加できます。複数選択に対応しています。追加後は設定画面で差分を確認して保存してください。

## 注意事項

この拡張機能は保護ルールを設定します。実行中のCodexで読み取りが拒否されるかは確認しません。他の拡張機能や外部MCP、環境変数・添付内容などから渡る情報も制御しません。

- Codexの権限プロファイル（ベータ機能）を使用します。対応状況はCodexのバージョン・OS・起動方法によって異なります。診断に表示する設定値は、実行中セッションの有効値とは限りません。
- 旧 `sandbox_mode` と競合すると保護設定を保存できません。リポジトリ内の `read-only` / `workspace-write` は画面から移行できますが、共通設定や複雑な設定はTOMLで手動移行してください。保護の解除もTOMLで行います。
- ファイル検索は初期値10,000件。「検索設定」で1〜1,000,000件に変更できます。`.git`・依存関係・ビルド出力などは検索対象外です。候補は300件、一致するファイルはパターンごとに200件まで表示します。これらの上限・除外は保護ルールには影響しません。
- 一致表示はパスのプレビューです。実際のglob処理やシンボリックリンク先の保護とは異なる場合があります。Linux・WSL・Windowsでは事前展開の深度に制限があり、必要に応じて `glob_scan_max_depth = 20` を追加します。`.env.example` も `.env.*` に一致します。
- インラインテーブル・配列テーブル・複雑なglobはTOMLで直接編集してください。シンボリックリンク経由の保存、仮想ワークスペース、未信頼ワークスペースには対応しません。Remote SSH / WSLではワークスペース側で動作します。

Codexの設定仕様は、公式の [権限プロファイル](https://learn.chatgpt.com/docs/permissions)・[設定の読み込み](https://learn.chatgpt.com/docs/config-file/config-basic)・[設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference) を参照してください。

## 開発

Node.js 22以降を推奨します。

```sh
npm ci
npm run check
npm test
npm run build

# ブラウザーでのUIテスト
npx playwright install chromium
npm run test:ui

# VSIXの生成
npm run package
```

VSCodeでこのフォルダーを開き、F5でExtension Development Hostを起動できます。
